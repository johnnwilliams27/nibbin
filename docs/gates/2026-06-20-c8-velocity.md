## Verdict: PASS (controller review)

Replaces the in-process `MemorySendRecordStore` TOCTOU (read-then-write, two statements) with a durable, atomic check-and-record before write-scope connectors (Instagram/QuickBooks) go live. 186/186 connector tests + 10/10 new client tests; lint clean; no new tsc errors.

- **Migration `20260620180000_send_velocity_store.sql`** (applied dev/staging/prod): `send_velocity_records` (append-only — `raise_append_only` update/truncate triggers, RLS service-role-only, FK cascade on account delete) + the `send_velocity_check_and_record` RPC.
- **Atomicity:** the RPC takes `pg_advisory_xact_lock(hashtextextended('nibbin:velocity:'||account_id))` so the count→check→insert triple can't interleave — two concurrent sends on one account can't both pass the cap. Account-scoped key (covers future multi-connector dispatch); a distinct lock namespace from `private.lock_account` so it can't deadlock with the credit/drip RPCs. `security definer`, `search_path=''`, `service_role`-only.
- **Fail-closed:** `PgSendRecordStore.checkAndConsume` maps any RPC error → `allowed:false` (deny), matching the durable-store convention. New-account cooldown cap computed in TS and passed as `p_daily_cap`.
- **Wiring:** prod `email.send` path now uses `PgSendRecordStore`; `MemorySendRecordStore` retained for tests.
