# Crystallization (Slice 4) — C-plan → durable B-spec — Design Spec

**Date:** 2026-06-18
**Status:** Approved-path (Slice 4 of the synthesis-core arc; user approved the architecture 2026-06-18). Builds on the Composer (2a #139 / 2b #141 / 2c #142) + Planner 3a (#150). Design context: `2026-06-17-agent-synthesis-design.md` §4 (B/C split — "C-plan … crystallizable → B"), §6/§7.
**Goal:** Turn a **successful supervised Planner run** (an ephemeral `plan_runs` row that reached `done`) into a **durable, recurring, validated B-spec** adopted as a real Nibbin — reusing the Composer's validator + adoption + hatch ceremony. Faithful by construction: the recurring agent does **exactly the chore the user just supervised**, on a schedule they choose.

## 1. The core idea + why it's a small slice
The Planner (C) discovers steps at runtime; the Composer (B) runs a fixed linear `steps[]`. Crystallization distills a successful C transcript into a B-spec. Almost all the machinery already exists — `validateComposedSpec` (fail-closed), `adoptComposedSpec` (the `adopt_nibbin` path, `templateKey=null`), and the Beat-2 hatch ceremony. The **new** parts are small: (1) a deterministic **extractor** (transcript → candidate `steps[]`), (2) a **crystallizability gate** (refuse plans that can't safely become recurring), (3) an LLM **soft-layer** proposal (name / suggested cadence / persona), (4) the **crystallize-preview UX** + provenance. No new runtime mechanism.

## 2. Derivation — deterministic extract + LLM soft-layer (locked)
The executable `steps[]` are **extracted deterministically from the transcript** — never re-synthesized by an LLM — so the durable agent is faithful to **what the human actually approved** during the supervised run (the load-bearing consent property; the validator already constrains safety, so faithfulness is the real concern).
- **Extract** (`crystallizeTranscript`): walk `plan_runs.transcript`; collect the **connector-capability / primitive picks** in order as `CapabilityStep`s. A **primitive pick** (`nudge.overdue-email`, `digest.morning`, …) maps 1:1 to a `CapabilityStep` (the primitive *is* the reusable, parameterized form — generalization is built in). For a raw atomic pick, generalize the args by dropping the run-specific binding (a concrete message id / invoice id) and keeping the reusable shape; if a pick's args cannot be generalized to a reusable step, the plan is **not crystallizable** (gate, §3).
- **LLM soft-layer** (`proposeCrystalSoftFields`): from the run's `goal` + the extracted steps, the model proposes ONLY `displayName`, a suggested `trigger` cadence, and `personaPolicy` — never the executable steps. Routed `frontier`/`origin:'chat'` (budget-drawn, COGS-recorded); no model key → deterministic defaults (a generic name + no suggested cadence; the user supplies them).

## 3. The crystallizability gate (refuse, don't paper over)
A plan run is crystallizable **only if all hold** (else `crystallize` returns `{ refused, reason }`, and the plan stays a re-runnable C-plan):
1. **Reached `done`** (not `failed`/`killed`/`needs_input`) AND produced **≥1 approved connector action** (a draft/effect), not a pure read/research run.
2. **No utility picks in the load-bearing path** — `web.search`/`web.fetch`/`scratchpad.*`/`memory.retrieve`/`ask_human` are runtime-*reasoning* aids, not B-steps. A run that searched the web or asked the human mid-task needed live judgment → refused ("better left as a task you re-run").
3. **Linear / no observation-dependent branching** — the extracted sequence must be a straight line of capability steps (the deterministic extract can't represent "if the result was X, do Y"). A transcript whose later picks depended on reasoning over an earlier observation in a non-reproducible way → refused.
4. **Every extracted step validates** under `validateComposedSpec` (capability ∈ registry, connector granted, args schema-checked, raw write rejected). Any failure → refused with the validator's reason.

The gate is fail-closed: ambiguous → refused. (This naturally selects the "genuine recurring chore" runs — which are the primitive-shaped ones that extract cleanly.)

## 4. Trigger consent (once → recurring)
The C-plan was `trigger:{kind:'once'}`. A recurring agent is a standing commitment, so the cadence is an **explicit human choice** at the preview. The soft-layer LLM *suggests* a cadence; the user picks/confirms a standard schedule (`daily.morning`, `weekly.monday`, …) or declines. We **never** auto-arm a recurring schedule. The chosen `TriggerDef` (with sane `debounceSecs`/`cooldownSecs`, mirroring Composer defaults) goes onto the B-spec; a `{kind:'user'}` manual trigger is always included so the user can also run it on demand.

## 5. School / autonomy (no trust transfer)
The crystallized agent **hatches as an egg** and runs the normal School path (drafts-for-approval → earns autonomy per-agent). The supervised approvals during the C run **do not transfer** as standing trust — consistent with the trust model ("trust is earned per-agent; freezes never decay, but also never teleport"). So the recurring agent re-earns its autonomy from scratch. This is the safe default and requires no School changes.

## 6. Flow + components
- **Entry:** from a `done` plan_run in the Planner run view, a "**Make this recurring**" affordance — shown on any `done` run; on click, `proposeCrystal` runs the gate server-side and either returns the candidate or surfaces the refusal reason inline (the UI never pre-judges crystallizability; the gate is the single authority).
- **`crystallize(planRunId)`** (`apps/web/lib/planner/crystallize.ts`): load the plan_run (account-scoped); run the gate (§3) → on refusal return `{refused, reason}`; else deterministically extract `steps[]`, call the soft-layer, assemble a candidate `AgentSpec` (`templateKey=null`, `steps`, `requiredConnectors` derived from the steps' `effectiveTools` via the Composer's `connectorsFor`, `triggers=[suggested?, {user}]`, the standard `curriculum` + `creditProfile`), run `validateComposedSpec` fail-closed, and return `{ spec, preview }`.
- **Preview + adopt** (server actions in `apps/web/app/app/planner/actions.ts`): `proposeCrystal(planRunId)` → returns the candidate + preview (steps in plain language, the chosen cadence, connectors needed, "hatches as an egg, drafts for your approval"); `adoptCrystal(planRunId, chosenName, chosenTrigger)` → re-extract deterministically + re-validate fail-closed (don't trust a round-tripped spec — re-derive from the source plan_run) → set the user-chosen trigger → **`adoptComposedSpec`** with `p_template_key=null` and the **source `plan_run_id`** recorded for provenance → the Beat-2 hatch ceremony.
- **Provenance:** record the originating `plan_run_id` on the adopted spec. Migration `20260618070000`: add `agent_specs.source_plan_run_id uuid null` (nullable, additive; FK to `plan_runs`), carried through `adopt_nibbin` (a new optional param) for audit/lineage. (Composer/template adopts pass null.)

## 7. Scope / boundaries
- **In (4):** the gate; the deterministic extractor; the soft-layer LLM proposal (+ no-key defaults); the crystallize-preview + adopt server actions + UX; the provenance column + `adopt_nibbin` param; tests + adversarial gate.
- **Out (later):** crystallizing non-linear / utility-dependent plans (refused by design); editing the crystallized spec before adopt (user picks name + trigger only); auto-*suggesting* crystallization (the user initiates); cross-run merging; the routing-reinforcement / Training Mode work.

## 8. Gating + tests
- **Gated** (`apps/web/lib/planner` + `packages/runtime` validator reuse + `apps/web/app/api`/actions + a small migration) → `docs/gates/` report + 4-reviewer adversarial gate + dev/staging/prod apply.
- **Security/faithfulness testing:** the executable steps are extracted from the trace, NEVER LLM-authored (a test asserts the soft-layer LLM output cannot introduce a step); the gate refuses utility-dependent / branching / non-`done` / read-only / un-generalizable runs (a test per refusal reason); `adoptCrystal` re-derives + re-validates from the source plan_run fail-closed (a tampered client payload can't inject steps); the crystallized agent hatches as an **egg** + is School-gated (no trust transfer); account-scoped (a foreign `planRunId` is refused); the trigger is the user's explicit choice (no default recurring arm).
- **Tests:** extract a primitive-shaped transcript → a valid B-spec whose steps == the run's picks; a web-search / ask_human / branching / read-only / non-`done` run is each refused with the right reason; `adoptCrystal` produces an egg Nibbin via `adoptComposedSpec` with `source_plan_run_id` set + the user trigger; no-key soft-layer falls back to deterministic defaults; foreign-account refusal; the full verify (tsc + vitest + eslint + next build).
